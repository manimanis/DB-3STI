Corrigé — Exercice 1 (4 pts)

Exercice 2 : Modélisation — Complexe « Takwira Arena » 5 points

Figure DC1A.1 — Schéma Relationnel de la base Takwira Arena (Terrain, Reservation, Equipe).
Le complexe de terrains de mini-foot Takwira Arena souhaite créer une base de données nommée takwira_db pour gérer ses réservations :
  • Chaque Terrain est identifié par un code (codeTer, ex. T01), possède un nom (nomTer), un type de gazon (typeGazon : Synthétique ou Hybride) et un tarif horaire en dinars (tarifH).
  • Chaque Équipe possède un numéro auto-incrémenté (idEq), un nom (nomEq), le téléphone de son capitaine (telCap) et sa ville (ville).
  • Chaque Réservation est identifiée par un numéro auto-incrémenté (numRes), possède une date (dateRes), une heure de début entière (heureDeb, ex. 18) et une durée en heures (dureeH). Un terrain accueille plusieurs réservations, mais chaque réservation concerne un seul terrain. Une équipe effectue plusieurs réservations, mais chaque réservation appartient à une seule équipe.
  1. Précisez le type de lien (1-N ou N-N) entre Terrain et Réservation, puis entre Équipe et Réservation. (1 pt)
  2. Écrivez la représentation textuelle complète des 3 tables (Terrain, Equipe, Reservation) en indiquant les clés primaires (#pk) et les clés étrangères (fk#). (2,5 pts)
  3. Indiquez dans quel ordre il faut créer ces 3 tables en SQL, puis dans quel ordre il faudrait les supprimer avec DROP TABLE. (1 pt)
  4. Pourquoi choisit-on le type VARCHAR plutôt que INT pour la colonne telCap ? (0,5 pt)
Corrigé — Exercice 2 (5 pts)

1. Types de liens (1 pt) : Terrain — Reservation : 1-N (0,5 pt) | Equipe — Reservation : 1-N (0,5 pt).

2. Modèle relationnel (2,5 pts) :

Terrain (#codeTer, nomTer, typeGazon, tarifH)
Equipe (#idEq, nomEq, telCap, ville)
Reservation (#numRes, dateRes, heureDeb, dureeH, codeTer#, idEq#)

3. Ordre (1 pt) : Création : Terrain et Equipe d'abord, puis Reservation (0,5 pt). Suppression : Reservation d'abord, puis Terrain et Equipe (0,5 pt).

4. Type de telCap (0,5 pt) : On ne fait pas de calculs arithmétiques sur un numéro de téléphone, et INT supprimerait les zéros initiaux ou interdirait le préfixe +216.

Exercice 3 : Langage de Définition de Données (LDD) 6 points

On suppose que la base takwira_db et la table Equipe(idEq INT AUTO_INCREMENT PRIMARY KEY, nomEq VARCHAR(40) NOT NULL, telCap VARCHAR(15) NOT NULL, ville VARCHAR(30) NOT NULL) sont déjà créées.

  1. Écrivez la requête SQL de création de la table Terrain respectant les règles suivantes : (1,5 pt)
    • codeTer : chaîne de 5 caractères max, clé primaire ;
    • nomTer : chaîne de 40 caractères max, obligatoire ;
    • typeGazon : liste fermée parmi 'Synthétique' et 'Hybride', obligatoire ;
    • tarifH : nombre décimal (7 chiffres dont 3 après la virgule), obligatoire et strictement positif.
  2. Écrivez la requête SQL de création de la table Reservation : (2,5 pts)
    • numRes : entier auto-incrémenté, clé primaire ;
    • dateRes : date obligatoire ; heureDeb : entier obligatoire ;
    • dureeH : entier obligatoire, valeur par défaut 1, compris entre 1 et 3 inclus ;
    • codeTer : clé étrangère vers Terrain(codeTer) avec ON DELETE RESTRICT ;
    • idEq : clé étrangère vers Equipe(idEq) avec ON DELETE CASCADE.
  3. Écrivez les 3 requêtes ALTER TABLE permettant d'effectuer les évolutions suivantes : (2 pts)
    • a) Ajouter à la table Equipe une colonne emailCap de type VARCHAR(80), facultative et unique. (1 pt)
    • b) Agrandir la colonne nomTer de la table Terrain à VARCHAR(60) (toujours obligatoire). (0,5 pt)
    • c) Renommer la colonne telCap de la table Equipe en telephone (VARCHAR(20) NOT NULL). (0,5 pt)
Corrigé — Exercice 3 : LDD (6 pts) 
-- 1. Création de Terrain (1,5 pt)
CREATE TABLE Terrain (
    codeTer   VARCHAR(5),
    nomTer    VARCHAR(40) NOT NULL,
    typeGazon ENUM('Synthétique', 'Hybride') NOT NULL,
    tarifH    DECIMAL(7,3) NOT NULL,
    CONSTRAINT pk_terrain PRIMARY KEY (codeTer),
    CONSTRAINT chk_tarif  CHECK (tarifH > 0)
);

-- 2. Création de Reservation (2,5 pts)
CREATE TABLE Reservation (
    numRes   INT AUTO_INCREMENT,
    dateRes  DATE NOT NULL,
    heureDeb INT  NOT NULL,
    dureeH   INT  NOT NULL DEFAULT 1,
    codeTer  VARCHAR(5) NOT NULL,
    idEq     INT        NOT NULL,
    CONSTRAINT pk_reservation PRIMARY KEY (numRes),
    CONSTRAINT chk_duree      CHECK (dureeH BETWEEN 1 AND 3),
    CONSTRAINT fk_res_terrain FOREIGN KEY (codeTer)
        REFERENCES Terrain(codeTer) ON DELETE RESTRICT,
    CONSTRAINT fk_res_equipe  FOREIGN KEY (idEq)
        REFERENCES Equipe(idEq) ON DELETE CASCADE
);

-- 3. Évolutions ALTER TABLE (2 pts)
ALTER TABLE Equipe  ADD emailCap VARCHAR(80) NULL UNIQUE;
ALTER TABLE Terrain MODIFY nomTer VARCHAR(60) NOT NULL;
ALTER TABLE Equipe  CHANGE telCap telephone VARCHAR(20) NOT NULL;

Exercice 4 : Manipulation des Données (LMD) et Intégrité 5 points

  1. Insertion multiple : Insérez en une seule requête les deux terrains suivants dans la table Terrain : (1,5 pt)
    • T01, Terrain Carthage, Synthétique, 60.000 DT
    • T02, Terrain Hannibal, Hybride, 80.000 DT
  2. Insertion simple : Insérez dans la table Equipe l'équipe 'Aigles Sousse', téléphone '22334455', ville 'Sousse', sans adresse e-mail (emailCap non renseigné). (1 pt)
  3. Mise à jour : Augmentez de 10.000 DT le tarif horaire (tarifH) de tous les terrains dont le type de gazon est 'Hybride'. (1 pt)
  4. Suppression ciblée : Supprimez de la table Reservation la réservation portant le numéro 15. (0,5 pt)
  5. Analyse d'intégrité : Expliquez précisément la réaction du SGBDR pour chacune des deux commandes ci-dessous : (1 pt — 0,5 pt × 2)
    • a) DELETE FROM Equipe WHERE idEq = 1; (sachant que l'équipe n°1 possède 3 réservations enregistrées).
    • b) INSERT INTO Reservation (dateRes, heureDeb, dureeH, codeTer, idEq) VALUES ('2026-12-01', 19, 2, 'T99', 1); (sachant que le terrain 'T99' n'existe pas dans Terrain).
Corrigé — Exercice 4 : LMD et Intégrité (5 pts) 
-- 1. Insertion multiple dans Terrain (1,5 pt)
INSERT INTO Terrain (codeTer, nomTer, typeGazon, tarifH) VALUES
('T01', 'Terrain Carthage', 'Synthétique', 60.000),
('T02', 'Terrain Hannibal', 'Hybride',     80.000);

-- 2. Insertion simple dans Equipe (1 pt)
INSERT INTO Equipe (nomEq, telephone, ville, emailCap)
VALUES ('Aigles Sousse', '22334455', 'Sousse', NULL);

-- 3. Mise à jour conditionnelle (1 pt)
UPDATE Terrain
SET tarifH = tarifH + 10
WHERE typeGazon = 'Hybride';

-- 4. Suppression ciblée (0,5 pt)
DELETE FROM Reservation
WHERE numRes = 15;

5. Analyse d'intégrité (1 pt) :
• a) L'équipe n°1 est supprimée ainsi que automatiquement ses 3 réservations dans Reservation, grâce à la clause ON DELETE CASCADE définie sur fk_res_equipe (0,5 pt).
• b) L'insertion est refusée pour violation d'intégrité référentielle : la clé étrangère codeTer = 'T99' ne correspond à aucune clé primaire existante dans la table mère Terrain (0,5 pt).
