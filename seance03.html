1. Prise en main : Interface graphique vs Langage SQL 15 min — Manip. guidée

Le langage SQL (Structured Query Language) permet de dialoguer avec le SGBDR (MariaDB / MySQL). Sa première partie, le LDD (Langage de Définition de Données), sert à construire la structure de la base (bases, tables, colonnes, contraintes).

Manipulation rapide sous phpMyAdmin :
  1. Ouvrez http://localhost/phpmyadmin dans votre navigateur.
  2. Cliquez sur Nouvelle base de données, créez une base nommée test_tp3 (interclassement utf8mb4_unicode_ci).
  3. Créez graphiquement une table TestCategorie contenant 2 colonnes : idCat (INT, PRIMARY, A_I) et libelle (VARCHAR 30).
  4. Avant de valider, cliquez sur le bouton Aperçu SQL : observez que phpMyAdmin ne fait que traduire vos clics en instructions SQL !

Pourquoi apprendre à écrire le SQL directement ? Parce qu'un script .sql est reproductible, rapide à corriger, facile à sauvegarder et indispensable dès qu'on relie la base à un site web ou un programme.

Guide Enseignant — Analyse comparative & Synthèse orale
  • Limites du mode graphique (clic-bouton) :
    • Lenteur et répétition : Recréer 10 tables avec 50 colonnes à la main prend un temps considérable et favorise les oublis de contraintes.
    • Non reproductible : Impossible de rejouer les clics automatiquement sur un autre serveur ou chez un hébergeur.
    • Pas d'automatisation : Les applications web (PHP, Python, Java) ne peuvent pas « cliquer » sur phpMyAdmin ; elles doivent impérativement envoyer des requêtes SQL textuelles.
  • Avantages d'un script .sql :
    • Vitesse & Versioning : Un script de 500 lignes s'exécute en quelques millisecondes et se sauvegarde dans un fichier texte léger.
    • Portabilité : Le même script s'importe indifféremment sous MariaDB, MySQL, en ligne de commande ou via phpMyAdmin.
  • Bilan à dicter : phpMyAdmin n'est qu'un traducteur visuel. Le véritable langage compris par le moteur de base de données est le SQL.

3. Synthèse : Types SQL et Syntaxe du LDD 15 min — Trace écrite

A. Principaux types de données MariaDB / MySQL

Type SQL Usage Exemple de valeur
INT Nombre entier (identifiants, quantités, âges) 1, 35, 2026
DECIMAL(M, D) Nombre décimal exact (prix, montants) : M chiffres max dont D après la virgule DECIMAL(10,3) → 2450.000
VARCHAR(N) Chaîne de caractères de longueur variable (jusqu'à N caractères) 'Sousse', 'P01'
DATE Date calendrier au format standard ISO AAAA-MM-JJ '2026-11-21'
ENUM('v1','v2',...) Liste fermée de valeurs prédéfinies ENUM('Disponible','En panne')

B. Syntaxe de création de base et de table

-- 1. Créer et sélectionner la base de données
CREATE DATABASE nom_base;
USE nom_base;

-- 2. Créer une table avec ses colonnes et contraintes
CREATE TABLE NomTable (
    colonne1 INT AUTO_INCREMENT,
    colonne2 VARCHAR(50) NOT NULL,
    colonne3 INT NOT NULL DEFAULT 0,
    col_fk   INT NOT NULL,
    CONSTRAINT pk_nom PRIMARY KEY (colonne1),
    CONSTRAINT fk_nom FOREIGN KEY (col_fk) REFERENCES TableMere(cle_mere)
);

C. Rôle des contraintes de base

  • NOT NULL : Interdit de laisser le champ vide lors de l'insertion.
  • AUTO_INCREMENT : Numérotation automatique (réservée à une colonne entière qui est clé primaire).
  • DEFAULT valeur : Attribue automatiquement une valeur par défaut si rien n'est saisi.
  • PRIMARY KEY (col1, ...) : Définit la clé primaire (simple ou composée).
  • FOREIGN KEY (col) REFERENCES TableMere(pk) : Relie la table fille à la table mère. Condition stricte : la colonne clé étrangère doit avoir exactement le même type que la clé primaire référencée.

4. TP guidé : Création de la base « boutique_info » 40 min — Sur machine

Ouvrez l'onglet SQL de phpMyAdmin (ou créez un fichier techstore_ldd.sql dans votre éditeur de code puis importez-le) et réalisez les étapes suivantes dans l'ordre :

  1. Étape 1 — Base de données : Écrivez les instructions permettant de créer la base boutique_info (en supprimant d'abord une éventuelle ancienne version avec DROP DATABASE IF EXISTS) puis de la sélectionner.
  2. Étape 2 — Tables mères : Créez les tables Client et Produit :
    • Client : idClt (entier auto-incrémenté, PK), nom (VARCHAR 40, obligatoire), prenom (VARCHAR 40, obligatoire), ville (VARCHAR 30, obligatoire), tel (VARCHAR 15, facultatif), dateInscr (DATE, obligatoire).
    • Produit : refProd (VARCHAR 10, PK), designation (VARCHAR 80, obligatoire), categorie (VARCHAR 30, obligatoire), prixUnit (DECIMAL(10,3), obligatoire), qteStock (INT, obligatoire, valeur par défaut 0).
  3. Étape 3 — Table fille Commande : Créez Commande avec numCmd (entier auto-incrémenté, PK), dateCmd (DATE, obligatoire) et idClt (clé étrangère référençant Client(idClt)).
  4. Étape 4 — Table d'association LigneCommande : Créez LigneCommande avec numCmd, refProd et qteCmd (INT, obligatoire). Déclarez la clé primaire composée (numCmd, refProd) ainsi que les deux clés étrangères vers Commande et Produit.
  5. Étape 5 — Vérification visuelle : Exécutez SHOW TABLES; puis DESCRIBE Commande;. Enfin, dans phpMyAdmin, cliquez sur la base boutique_info puis sur l'onglet Concepteur (Designer) : vérifiez que les 3 flèches de relations apparaissent bien entre les 4 tables.
Corrigé — Script LDD complet (boutique_info) 
-- Étape 1 : Création et sélection de la base
DROP DATABASE IF EXISTS boutique_info;
CREATE DATABASE boutique_info
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

USE boutique_info;

-- Étape 2 : Tables mères (indépendantes)
CREATE TABLE Client (
    idClt     INT AUTO_INCREMENT,
    nom       VARCHAR(40) NOT NULL,
    prenom    VARCHAR(40) NOT NULL,
    ville     VARCHAR(30) NOT NULL,
    tel       VARCHAR(15) NULL,
    dateInscr DATE        NOT NULL,
    CONSTRAINT pk_client PRIMARY KEY (idClt)
);

CREATE TABLE Produit (
    refProd     VARCHAR(10),
    designation VARCHAR(80)   NOT NULL,
    categorie   VARCHAR(30)   NOT NULL,
    prixUnit    DECIMAL(10,3) NOT NULL,
    qteStock    INT           NOT NULL DEFAULT 0,
    CONSTRAINT pk_produit PRIMARY KEY (refProd)
);

-- Étape 3 : Table fille Commande (référence Client)
CREATE TABLE Commande (
    numCmd  INT AUTO_INCREMENT,
    dateCmd DATE NOT NULL,
    idClt   INT  NOT NULL,
    CONSTRAINT pk_commande   PRIMARY KEY (numCmd),
    CONSTRAINT fk_cmd_client FOREIGN KEY (idClt) REFERENCES Client(idClt)
);

-- Étape 4 : Table d'association LigneCommande (PK composée + 2 FK)
CREATE TABLE LigneCommande (
    numCmd  INT,
    refProd VARCHAR(10),
    qteCmd  INT NOT NULL,
    CONSTRAINT pk_ligne    PRIMARY KEY (numCmd, refProd),
    CONSTRAINT fk_lig_cmd  FOREIGN KEY (numCmd)  REFERENCES Commande(numCmd),
    CONSTRAINT fk_lig_prod FOREIGN KEY (refProd) REFERENCES Produit(refProd)
);

5. Atelier « Chasse aux bugs SQL » 15 min

Chaque extrait SQL ci-dessous provoque une erreur lors de son exécution dans MariaDB / phpMyAdmin. Identifiez l'erreur et expliquez comment la corriger.

Bug 1 — Création d'une table fille trop tôt

CREATE TABLE Commande (
    numCmd INT PRIMARY KEY,
    idClt  INT,
    FOREIGN KEY (idClt) REFERENCES Client(idClt)
);
CREATE TABLE Client (
    idClt INT PRIMARY KEY,
    nom   VARCHAR(40)
);
Corrigé — Bug 1 Erreur d'ordre : Commande référence Client avant que la table Client n'existe. Il faut toujours exécuter CREATE TABLE Client avant CREATE TABLE Commande.

Bug 2 — Clé étrangère incompatible

-- Sachant que Produit.refProd est déclaré en VARCHAR(10)
CREATE TABLE LigneCommande (
    numCmd  INT,
    refProd INT,
    qteCmd  INT NOT NULL,
    PRIMARY KEY (numCmd, refProd),
    FOREIGN KEY (refProd) REFERENCES Produit(refProd)
);
Corrigé — Bug 2 Incompatibilité de type : Dans LigneCommande, refProd est déclaré en INT alors que Produit.refProd est un VARCHAR(10). Les deux colonnes doivent avoir exactement le même type (VARCHAR(10)).

Bug 3 — Double erreur de syntaxe

CREATE TABLE Produit (
    refProd  VARCHAR(10) AUTO_INCREMENT PRIMARY KEY,
    prixUnit DECIMAL(10,3) NOT NULL,
);
Corrigé — Bug 3 1) AUTO_INCREMENT ne s'applique qu'à un type entier (INT), jamais à un VARCHAR.
2) Il y a une virgule en trop après NOT NULL juste avant la parenthèse fermante );.

6. Quiz éclair de clôture 15 min

1. Choix de type : Pourquoi stocke-t-on un numéro de téléphone ou un code postal en VARCHAR plutôt qu'en INT ?
Réponse : Parce qu'on n'effectue pas de calculs arithmétiques dessus, et un type INT supprimerait les zéros initiaux (ex. 07... deviendrait 7...) ou empêcherait des caractères comme « +216 ».
2. Précision : Quelle est la valeur maximale stockable dans un champ de type DECIMAL(5,2) ?
Réponse : 999.99 (5 chiffres au total : 3 avant la virgule et 2 après).
3. Vrai ou Faux : « On peut mettre deux colonnes AUTO_INCREMENT dans une même table. »
Réponse : Faux — Une table ne peut contenir qu'une seule colonne AUTO_INCREMENT, qui doit être une clé (en pratique la clé primaire).
4. Contrainte : Que fait SQL si l'on insère un nouveau produit sans préciser de valeur pour qteStock (déclaré INT NOT NULL DEFAULT 0) ?
Réponse : Il accepte l'insertion et attribue automatiquement la valeur 0 à qteStock.
5. Commande utile : Quelle commande SQL permet d'afficher la structure (colonnes, types, clés) d'une table déjà créée ?
Réponse : DESCRIBE NomTable; (ou DESC NomTable;).
