Présentation du domaine — Club Sportif « FitZone » :
Le complexe sportif FitZone souhaite informatiser la gestion de ses coachs, de ses activités sportives, de ses adhérents et de leurs inscriptions selon les règles de gestion suivantes :
  • Chaque Coach possède un identifiant numérique auto-incrémenté (idCoach), un nom (nomCoach), une spécialité (specialite) et un numéro de téléphone (tel).
  • Chaque Activité est identifiée par un code (codeAct, ex. ACT01), possède un libellé (libelle), une salle (salle) et un tarif mensuel en DT (tarifMois). Un coach peut encadrer plusieurs activités, mais chaque activité est encadrée par un seul coach.
  • Chaque Adhérent est identifié par un numéro auto-incrémenté (idAdh) et décrit par son nom, son prénom, sa ville, son téléphone (facultatif) et sa date de naissance (dateNaiss).
  • Un adhérent peut s'inscrire à plusieurs activités, et une même activité accueille plusieurs adhérents. Chaque Inscription précise la date d'inscription (dateInscr) et le nombre de mois payés (nbMois).

  2. Un stagiaire propose d'ajouter la colonne age dans la table Adherent en plus de dateNaiss, et de fusionner nom et prenom dans un seul champ nomComplet. Quelle erreur de conception commet-il dans chacun des deux cas ? (1 pt)
  3. Écrivez la représentation textuelle complète des 4 tables de la base fitzone_db (Coach, Activite, Adherent, Inscription) en utilisant la notation #clePrimaire et cleEtrangere#. (1,5 pt)
  4. Dans quel ordre doit-on créer ces 4 tables en SQL pour respecter l'intégrité référentielle ? (0,5 pt)
Corrigé — Partie 1 (4 pts)

1. Types de liens (1 pt) :
• Coach — Activite : 1-N (un coach encadre plusieurs activités, une activité a un seul coach).
• Adherent — Activite : N-N (un adhérent peut s'inscrire à plusieurs activités, et réciproquement), d'où la table d'association Inscription.

2. Erreurs de conception (1 pt) :
• age est un attribut calculé (dérivé) à partir de dateNaiss : il deviendrait vite obsolète.
• nomComplet viole la règle d'atomicité (attribut composé qui empêche de trier ou filtrer facilement par nom de famille).

3. Modèle relationnel (1,5 pt) :

Coach (#idCoach, nomCoach, specialite, tel)
Activite (#codeAct, libelle, salle, tarifMois, idCoach#)
Adherent (#idAdh, nom, prenom, ville, tel, dateNaiss)
Inscription (#idAdh#, #codeAct#, dateInscr, nbMois)

4. Ordre de création (0,5 pt) : Coach et Adherent d'abord (tables mères indépendantes), puis Activite (référence Coach), et enfin Inscription (référence Adherent et Activite).

Partie 2 : Langage de Définition de Données (LDD) 5 points

  1. Créez la base de données fitzone_db (après suppression si elle existe déjà) et sélectionnez-la. (0,5 pt)
  2. Créez les tables mères Coach et Adherent : (1 pt)
    • Coach : idCoach (entier auto-incrémenté, PK), nomCoach (VARCHAR 40, obligatoire), specialite (VARCHAR 30, obligatoire), tel (VARCHAR 15, obligatoire et unique).
    • Adherent : idAdh (entier auto-incrémenté, PK), nom (VARCHAR 40, obligatoire), prenom (VARCHAR 40, obligatoire), ville (VARCHAR 30, obligatoire), tel (VARCHAR 15, facultatif), dateNaiss (DATE, obligatoire).
  3. Créez la table Activite : codeAct (VARCHAR 10, PK), libelle (VARCHAR 50, obligatoire), salle (VARCHAR 20, obligatoire), tarifMois (DECIMAL(8,3), obligatoire et strictement positif), idCoach (clé étrangère vers Coach avec ON DELETE RESTRICT et ON UPDATE CASCADE). (1,5 pt)
  4. Créez la table Inscription : idAdh, codeAct, dateInscr (DATE, obligatoire), nbMois (INT, valeur par défaut 1, compris entre 1 et 12 inclus). Déclarez la clé primaire composée et les deux clés étrangères (avec ON DELETE CASCADE vers Adherent et ON DELETE RESTRICT vers Activite). (1 pt)
  5. Évolution de structure (ALTER TABLE) : (1 pt)
    • Ajoutez à la table Adherent une colonne email (VARCHAR(80), facultative et unique).
    • Agrandissez la colonne salle de la table Activite à VARCHAR(35) (toujours obligatoire).
Corrigé — Partie 2 : Script LDD complet (5 pts) 
-- 1. Base de données (0,5 pt)
DROP DATABASE IF EXISTS fitzone_db;
CREATE DATABASE fitzone_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE fitzone_db;

-- 2. Tables mères Coach et Adherent (1 pt)
CREATE TABLE Coach (
    idCoach    INT AUTO_INCREMENT,
    nomCoach   VARCHAR(40) NOT NULL,
    specialite VARCHAR(30) NOT NULL,
    tel        VARCHAR(15) NOT NULL,
    CONSTRAINT pk_coach     PRIMARY KEY (idCoach),
    CONSTRAINT uq_coach_tel UNIQUE (tel)
);

CREATE TABLE Adherent (
    idAdh     INT AUTO_INCREMENT,
    nom       VARCHAR(40) NOT NULL,
    prenom    VARCHAR(40) NOT NULL,
    ville     VARCHAR(30) NOT NULL,
    tel       VARCHAR(15) NULL,
    dateNaiss DATE        NOT NULL,
    CONSTRAINT pk_adherent PRIMARY KEY (idAdh)
);

-- 3. Table Activite (1,5 pt)
CREATE TABLE Activite (
    codeAct   VARCHAR(10),
    libelle   VARCHAR(50)  NOT NULL,
    salle     VARCHAR(20)  NOT NULL,
    tarifMois DECIMAL(8,3) NOT NULL,
    idCoach   INT          NOT NULL,
    CONSTRAINT pk_activite    PRIMARY KEY (codeAct),
    CONSTRAINT chk_tarif      CHECK (tarifMois > 0),
    CONSTRAINT fk_act_coach   FOREIGN KEY (idCoach)
        REFERENCES Coach(idCoach)
        ON DELETE RESTRICT ON UPDATE CASCADE
);

-- 4. Table d'association Inscription (1 pt)
CREATE TABLE Inscription (
    idAdh     INT,
    codeAct   VARCHAR(10),
    dateInscr DATE NOT NULL,
    nbMois    INT  NOT NULL DEFAULT 1,
    CONSTRAINT pk_inscr       PRIMARY KEY (idAdh, codeAct),
    CONSTRAINT chk_nb_mois    CHECK (nbMois BETWEEN 1 AND 12),
    CONSTRAINT fk_inscr_adh   FOREIGN KEY (idAdh)
        REFERENCES Adherent(idAdh)
        ON DELETE CASCADE ON UPDATE CASCADE,
    CONSTRAINT fk_inscr_act   FOREIGN KEY (codeAct)
        REFERENCES Activite(codeAct)
        ON DELETE RESTRICT ON UPDATE CASCADE
);

-- 5. Évolutions ALTER TABLE (1 pt)
ALTER TABLE Adherent ADD email VARCHAR(80) NULL UNIQUE;
ALTER TABLE Activite MODIFY salle VARCHAR(35) NOT NULL;

Partie 4 : Interrogation de la Base (Requêtes SELECT) 8 points

Rappel méthodologique : Toutes les jointures doivent être rédigées sous forme de jointures implicites dans la clause WHERE (FROM T1, T2 WHERE T1.pk = T2.fk) avec des alias de tables si nécessaire.
  1. Filtrage et NULL : Afficher l'identifiant, le nom et le prénom des adhérents habitant à 'Sousse' qui n'ont pas renseigné de numéro de téléphone. (0,5 pt)
  2. Motifs et intervalles : Afficher le code, le libellé et le tarif mensuel des activités dont le tarif est compris entre 90 et 150 DT inclus et dont le libellé contient le mot 'Fitness' ou 'Intense', triés par tarif décroissant. (0,5 pt)
  3. Fonctions scalaires (chaînes et dates) : Afficher le nom complet formaté des adhérents sous la forme KHELIFI Youssef (alias Adherent) et leur année de naissance (alias Annee_Naiss), uniquement pour ceux nés en 2008 ou 2009. (1 pt)
  4. Regroupement et HAVING : Afficher pour chaque ville le nombre d'adhérents inscrits (alias Nb_Adherents), en ne conservant que les villes qui comptent au moins 2 adhérents, triées par effectif décroissant. (1 pt)
  5. Jointure implicite (2 tables) : Afficher le libellé de chaque activité, sa salle, son tarif mensuel ainsi que le nom (nomCoach) et la spécialité du coach qui l'encadre, triés par nom de coach croissant. (1 pt)
  6. Jointure implicite (3 tables) et calcul : Afficher le détail complet des inscriptions réalisées au premier trimestre 2026 (mois 1, 2 ou 3) : nom et prénom de l'adhérent, libellé de l'activité, date d'inscription, nombre de mois et montant payé (tarifMois * nbMois, alias Montant_DT). (1 pt)

  8. Synthèse (4 tables + WHERE + GROUP BY + HAVING) : En ne tenant compte que des adhérents habitant à 'Sousse', afficher le nom de chaque coach (nomCoach) et le chiffre d'affaires total généré par ses activités auprès des clients soussiens (CA_Sousse), uniquement pour les coachs dont ce chiffre d'affaires dépasse 500 DT. (1,5 pt)
Corrigé — Partie 4 : Requêtes SELECT (8 pts) 
-- 1. Adhérents de Sousse sans téléphone (0,5 pt) → 1 ligne : Amine Jaziri
SELECT idAdh, nom, prenom
FROM Adherent
WHERE ville = 'Sousse' AND tel IS NULL;

-- 2. Activités entre 90 et 150 DT contenant Fitness ou Intense (0,5 pt) → ACT05, ACT01
SELECT codeAct, libelle, tarifMois
FROM Activite
WHERE tarifMois BETWEEN 90 AND 150
  AND (libelle LIKE '%Fitness%' OR libelle LIKE '%Intense%')
ORDER BY tarifMois DESC;

-- 3. Nom complet formaté et année de naissance 2008/2009 (1 pt) → 4 lignes
SELECT CONCAT(UPPER(nom), ' ', prenom) AS Adherent,
       YEAR(dateNaiss) AS Annee_Naiss
FROM Adherent
WHERE YEAR(dateNaiss) IN (2008, 2009);

-- 4. Villes comptant au moins 2 adhérents (1 pt) → Sousse (3), Tunis (2)
SELECT ville, COUNT(*) AS Nb_Adherents
FROM Adherent
GROUP BY ville
HAVING COUNT(*) >= 2
ORDER BY Nb_Adherents DESC;

-- 5. Jointure implicite 2 tables : Activite + Coach (1 pt) → 5 lignes
SELECT Act.libelle, Act.salle, Act.tarifMois, C.nomCoach, C.specialite
FROM Activite Act, Coach C
WHERE Act.idCoach = C.idCoach
ORDER BY C.nomCoach ASC;

-- 6. Jointure implicite 3 tables : T1 2026 + montant payé (1 pt) → 6 lignes
SELECT A.nom, A.prenom, Act.libelle, I.dateInscr, I.nbMois,
       (Act.tarifMois * I.nbMois) AS Montant_DT
FROM Adherent A, Inscription I, Activite Act
WHERE A.idAdh = I.idAdh
  AND I.codeAct = Act.codeAct
  AND YEAR(I.dateInscr) = 2026
  AND MONTH(I.dateInscr) IN (1, 2, 3);

-- 7. Jointure 2/3 tables + GROUP BY : Recette par activité (1,5 pt)
-- Résultats : ACT01 (3 inscrits, 960 DT), ACT04 (2, 880 DT), ACT05 (1, 300 DT), ACT02 (1, 270 DT), ACT03 (1, 170 DT)
SELECT Act.codeAct, Act.libelle,
       COUNT(*) AS Nb_Inscrits,
       SUM(Act.tarifMois * I.nbMois) AS Recette_DT
FROM Activite Act, Inscription I
WHERE Act.codeAct = I.codeAct
GROUP BY Act.codeAct, Act.libelle
ORDER BY Recette_DT DESC;

-- 8. Jointure 4 tables + WHERE + GROUP BY + HAVING (1,5 pt)
-- Adhérents de Sousse : Ben Youssef (360+120+270+480 = 1230 DT > 500) ; Gharbi (220 DT) ; Trabelsi (170 DT)
SELECT C.nomCoach,
       SUM(Act.tarifMois * I.nbMois) AS CA_Sousse
FROM Coach C, Activite Act, Inscription I, Adherent A
WHERE C.idCoach = Act.idCoach
  AND Act.codeAct = I.codeAct
  AND I.idAdh = A.idAdh
  AND A.ville = 'Sousse'
GROUP BY C.idCoach, C.nomCoach
HAVING SUM(Act.tarifMois * I.nbMois) > 500;
