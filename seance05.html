1. Accroche : Par quelle table commencer ? 15 min — Oral

Notre base boutique_info (TechStore) est désormais construite et sécurisée (séances 3 et 4), mais ses 4 tables sont encore vides. Nous passons aujourd'hui au LMD (Langage de Manipulation de Données) pour y ajouter, modifier et supprimer des enregistrements.

Question d'ouverture :
  1. Peut-on insérer immédiatement la commande n°1 du client n°1 dans la table Commande avant d'avoir rempli la table Client ? Pourquoi ?
  2. Indiquez dans quel ordre il faut insérer les données dans les 4 tables : Client, Produit, Commande, LigneCommande.
  3. Indiquez dans quel ordre il faudrait les vider avec DELETE.
Corrigé — Règle d'ordre (Mères ↔ Filles)
  • Insertion : Toujours les tables mères avant les tables filles → Client et Produit d'abord, puis Commande, et enfin LigneCommande.
  • Suppression : Exactement l'ordre inverse (filles avant mères) → LigneCommande → Commande → Client et Produit.

2. Synthèse : Les 3 instructions de manipulation (LMD) 20 min — Trace écrite

Figure 5.1 — Ordre d'intégrité LMD : insertion descendante (mères d'abord) et suppression ascendante (filles d'abord).

A. Insérer des enregistrements : INSERT INTO

-- 1. Insertion simple (recommandé : préciser la liste des colonnes)
INSERT INTO Client (nom, prenom, ville, tel, dateInscr)
VALUES ('Ben Salem', 'Sami', 'Sousse', '22451200', '2025-09-12');

-- 2. Insertion multiple (plusieurs lignes en une seule requête)
INSERT INTO Produit (refProd, designation, categorie, prixUnit, qteStock)
VALUES
  ('P01', 'PC Portable Lenovo ThinkPad E15', 'Ordinateur', 2450.000, 8),
  ('P02', 'PC Portable Dell Inspiron 15',    'Ordinateur', 1890.000, 5);
  • Les chaînes de caractères et les dates (format 'AAAA-MM-JJ') s'écrivent entre apostrophes simples '...'. Les nombres s'écrivent sans apostrophes (avec un point décimal .).
  • On peut omettre une colonne AUTO_INCREMENT (elle se remplit seule), une colonne avec DEFAULT, ou une colonne facultative (ou lui passer explicitement NULL sans apostrophes).

B. Modifier des enregistrements : UPDATE

UPDATE NomTable
SET col1 = nouvelle_valeur1, col2 = nouvelle_valeur2
WHERE condition;

C. Supprimer des enregistrements : DELETE

DELETE FROM NomTable
WHERE condition;
PIÈGE CRITIQUE — L'oubli de la clause WHERE :
• Un UPDATE Produit SET prixUnit = 100; sans WHERE écrase le prix de TOUS les produits de la table !
• Un DELETE FROM Client; sans WHERE vide intégralement la table !
Réflexe professionnel : Toujours vérifier la condition avec un SELECT * FROM Table WHERE ...; avant d'exécuter un UPDATE ou un DELETE.

4. Laboratoire : Provoquer et comprendre les erreurs d'intégrité 20 min — Sur machine

Testez volontairement chacune des 4 requêtes suivantes dans phpMyAdmin, notez la réaction du SGBDR et expliquez quelle contrainte a protégé la base :

Test 1 — Clé étrangère inexistante à l'insertion

INSERT INTO Commande (dateCmd, idClt) VALUES ('2026-05-01', 99);
Explication — Test 1 Refusé (Erreur FK) : Le client idClt = 99 n'existe pas dans la table mère Client. La contrainte fk_cmd_client bloque l'insertion.

Test 2 — Violation d'une contrainte CHECK

INSERT INTO Produit (refProd, designation, categorie, prixUnit, qteStock)
VALUES ('P99', 'Câble HDMI', 'Accessoire', -15.000, 10);
Explication — Test 2 Refusé (Erreur CHECK) : La contrainte chk_prix impose prixUnit > 0. Une valeur négative (-15.000) est immédiatement rejetée.

Test 3 — Suppression bloquée (ON DELETE RESTRICT)

DELETE FROM Client WHERE idClt = 1;
Explication — Test 3 Refusé (RESTRICT) : Le client 1 (Sami) possède les commandes 1 et 3 dans Commande. Grâce à ON DELETE RESTRICT, sa suppression est interdite. (En revanche, supprimer le client 6 — Nour — qui n'a aucune commande, fonctionnerait.)

Test 4 — Suppression automatique (ON DELETE CASCADE)

-- On crée une commande test n°7 avec 1 ligne, puis on la supprime
INSERT INTO Commande (numCmd, dateCmd, idClt) VALUES (7, '2026-05-10', 6);
INSERT INTO LigneCommande (numCmd, refProd, qteCmd) VALUES (7, 'P03', 2);

DELETE FROM Commande WHERE numCmd = 7;
SELECT * FROM LigneCommande WHERE numCmd = 7;
Explication — Test 4 Accepté + Cascade : La suppression de la commande 7 réussit et le SELECT renvoie 0 ligne : la ligne (7, 'P03', 2) dans LigneCommande a été effacée automatiquement grâce à ON DELETE CASCADE.

5. Application en autonomie : Scénario de gestion quotidienne 15 min

Écrivez les 5 requêtes SQL correspondant aux opérations suivantes sur boutique_info (sur feuille, sans modifier votre jeu de données final) :

  1. Ajouter un nouveau client : Karim Mansour, habitant à Nabeul, sans numéro de téléphone, inscrit le 2026-05-12.
  2. Mettre à jour la ville et le téléphone de la cliente Aya Mansouri (idClt = 4) : nouvelle ville 'Monastir' et nouveau téléphone '52102030'.
  3. Appliquer une remise de 50.000 DT sur le prix de tous les produits de la catégorie 'Ordinateur' dont le prix dépasse 2000.000 DT.
  4. Supprimer de la table Produit tous les articles de catégorie 'Stockage' qui sont en rupture de stock (qteStock = 0) et n'ont jamais été commandés.
  5. Enregistrer une commande pour le client 6 à la date du 2026-05-15 (en supposant qu'elle reçoit le numéro 8), puis y ajouter 3 exemplaires du produit 'P05'.
Corrigé — Requêtes LMD en autonomie 
-- 1. Nouveau client sans téléphone
INSERT INTO Client (nom, prenom, ville, tel, dateInscr)
VALUES ('Mansour', 'Karim', 'Nabeul', NULL, '2026-05-12');

-- 2. Mise à jour de 2 colonnes en une seule requête
UPDATE Client
SET ville = 'Monastir', tel = '52102030'
WHERE idClt = 4;

-- 3. Remise conditionnelle (double critère dans WHERE)
UPDATE Produit
SET prixUnit = prixUnit - 50
WHERE categorie = 'Ordinateur' AND prixUnit > 2000;

-- 4. Suppression ciblée
DELETE FROM Produit
WHERE categorie = 'Stockage' AND qteStock = 0;

-- 5. Insertion dans Commande puis dans LigneCommande
INSERT INTO Commande (numCmd, dateCmd, idClt) VALUES (8, '2026-05-15', 6);
INSERT INTO LigneCommande (numCmd, refProd, qteCmd) VALUES (8, 'P05', 3);

6. Quiz éclair de clôture 10 min

1. Danger : Que se passe-t-il si l'on exécute DELETE FROM Produit; sans clause WHERE ?
Réponse : Le SGBDR tente de supprimer TOUS les enregistrements de la table Produit (ici bloqué uniquement si des lignes sont référencées par LigneCommande avec RESTRICT).
2. Syntaxe : Quelle est l'erreur dans la requête INSERT INTO Client (nom, tel) VALUES ('Ali', 'NULL'); ?
Réponse : 'NULL' entre apostrophes insère le texte littéral "NULL" (4 lettres) au lieu d'une valeur absente. Il faut écrire NULL sans apostrophes.
3. Différence LDD / LMD : Quelle est la différence entre DELETE FROM Produit; et DROP TABLE Produit; ?
Réponse : DELETE (LMD) supprime uniquement les lignes (la structure de la table reste vide et utilisable). DROP TABLE (LDD) détruit définitivement la table et sa structure.
4. Syntaxe UPDATE : Dans UPDATE Client SET ville = 'Sfax' AND tel = '20112233' WHERE idClt = 2;, quel symbole est faux ?
Réponse : Dans la clause SET, on sépare les colonnes par une virgule (,) et jamais par AND : SET ville = 'Sfax', tel = '20112233'.
5. Format de date : Comment écrit-on le 5 février 2026 dans une requête INSERT INTO sous MariaDB / MySQL ?
Réponse : '2026-02-05' (format ISO AAAA-MM-JJ entre apostrophes simples).
