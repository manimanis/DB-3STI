Présentation du domaine — Agence d'Excursions « TunisiTrip » :
L'agence de tourisme local TunisiTrip souhaite informatiser la gestion de ses guides, de ses excursions, de ses voyageurs et de leurs réservations selon les règles de gestion suivantes :
  • Chaque Guide possède un identifiant numérique auto-incrémenté (idGuide), un nom (nomGuide), une langue principale (langue) et un numéro de téléphone (tel).
  • Chaque Excursion est identifiée par un code (codeExc, ex. EXC01), possède un titre (titre), une destination (destination) et un prix par personne en DT (prixPers). Un guide peut encadrer plusieurs excursions, mais chaque excursion est encadrée par un seul guide.
  • Chaque Voyageur est identifié par un numéro auto-incrémenté (idVoy) et décrit par son nom, son prénom, sa ville, son téléphone (facultatif) et sa date de naissance (dateNaiss).
  • Un voyageur peut réserver plusieurs excursions, et une même excursion accueille plusieurs voyageurs. Chaque Réservation précise la date de réservation (dateRes) et le nombre de places réservées (nbPlaces).

Corrigé — Partie 1 (4 pts)

1. Types de liens (1 pt) :
• Guide — Excursion : 1-N (un guide encadre plusieurs excursions, une excursion a un seul guide).
• Voyageur — Excursion : N-N (un voyageur peut réserver plusieurs excursions, et réciproquement), d'où la table d'association Reservation.

2. Erreurs de conception (1 pt) :
• montantTotal est un attribut calculé (dérivé) à partir de prixPers * nbPlaces : il crée un risque d'incohérence si le tarif ou le nombre de places change.
• adresseComplete viole la règle d'atomicité (attribut composé qui empêche de filtrer ou regrouper facilement par ville ou code postal).

3. Modèle relationnel (1,5 pt) :

Guide (#idGuide, nomGuide, langue, tel)
Excursion (#codeExc, titre, destination, prixPers, idGuide#)
Voyageur (#idVoy, nom, prenom, ville, tel, dateNaiss)
Reservation (#idVoy#, #codeExc#, dateRes, nbPlaces)

4. Ordre de suppression (0,5 pt) : Filles avant mères : Reservation d'abord, puis Excursion, et enfin Guide et Voyageur.

  1. Créez la base de données tunisitrip_db (après suppression si elle existe déjà) et sélectionnez-la. (0,5 pt)
  2. Créez les tables mères Guide et Voyageur : (1 pt)
    • Guide : idGuide (entier auto-incrémenté, PK), nomGuide (VARCHAR 40, obligatoire), langue (VARCHAR 30, obligatoire), tel (VARCHAR 15, obligatoire et unique).

Corrigé — Partie 2 : Script LDD complet (5 pts) 
-- 1. Base de données (0,5 pt)
DROP DATABASE IF EXISTS tunisitrip_db;
CREATE DATABASE tunisitrip_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE tunisitrip_db;

-- 2. Tables mères Guide et Voyageur (1 pt)
CREATE TABLE Guide (
    idGuide  INT AUTO_INCREMENT,
    nomGuide VARCHAR(40) NOT NULL,
    langue   VARCHAR(30) NOT NULL,
    tel      VARCHAR(15) NOT NULL,
    CONSTRAINT pk_guide     PRIMARY KEY (idGuide),
    CONSTRAINT uq_guide_tel UNIQUE (tel)
);

CREATE TABLE Voyageur (
    idVoy     INT AUTO_INCREMENT,
    nom       VARCHAR(40) NOT NULL,
    prenom    VARCHAR(40) NOT NULL,
    ville     VARCHAR(30) NOT NULL,
    tel       VARCHAR(15) NULL,
    dateNaiss DATE        NOT NULL,
    CONSTRAINT pk_voyageur PRIMARY KEY (idVoy)
);

-- 3. Table Excursion (1,5 pt)
CREATE TABLE Excursion (
    codeExc     VARCHAR(10),
    titre       VARCHAR(50)  NOT NULL,
    destination VARCHAR(30)  NOT NULL,
    prixPers    DECIMAL(8,3) NOT NULL,
    idGuide     INT          NOT NULL,
    CONSTRAINT pk_excursion   PRIMARY KEY (codeExc),
    CONSTRAINT chk_prix_pers  CHECK (prixPers > 0),
    CONSTRAINT fk_exc_guide   FOREIGN KEY (idGuide)
        REFERENCES Guide(idGuide)
        ON DELETE RESTRICT ON UPDATE CASCADE
);

-- 4. Table d'association Reservation (1 pt)
CREATE TABLE Reservation (
    idVoy    INT,
    codeExc  VARCHAR(10),
    dateRes  DATE NOT NULL,
    nbPlaces INT  NOT NULL DEFAULT 1,
    CONSTRAINT pk_res        PRIMARY KEY (idVoy, codeExc),
    CONSTRAINT chk_nb_places CHECK (nbPlaces BETWEEN 1 AND 10),
    CONSTRAINT fk_res_voy    FOREIGN KEY (idVoy)
        REFERENCES Voyageur(idVoy)
        ON DELETE CASCADE ON UPDATE CASCADE,
    CONSTRAINT fk_res_exc    FOREIGN KEY (codeExc)
        REFERENCES Excursion(codeExc)
        ON DELETE RESTRICT ON UPDATE CASCADE
);

-- 5. Évolutions ALTER TABLE (1 pt)
ALTER TABLE Voyageur  ADD email VARCHAR(80) NULL UNIQUE;
ALTER TABLE Excursion MODIFY destination VARCHAR(50) NOT NULL;

Rappel méthodologique : Toutes les jointures doivent être rédigées sous forme de jointures implicites dans la clause WHERE (FROM T1, T2 WHERE T1.pk = T2.fk) avec des alias de tables si nécessaire.

Corrigé — Partie 4 : Requêtes SELECT (8 pts) 
-- 1. Voyageurs de Sousse sans téléphone (0,5 pt) → 1 ligne : Rayen Khelifi
SELECT idVoy, nom, prenom
FROM Voyageur
WHERE ville = 'Sousse' AND tel IS NULL;

-- 2. Excursions entre 100 et 200 DT contenant Désert ou Dunes (0,5 pt) → EXC01 (180), EXC04 (160)
SELECT codeExc, titre, prixPers
FROM Excursion
WHERE prixPers BETWEEN 100 AND 200
  AND (titre LIKE '%Désert%' OR titre LIKE '%Dunes%')
ORDER BY prixPers DESC;

-- 3. Nom complet formaté et année de naissance 2008/2009 (1 pt) → 4 lignes
SELECT CONCAT(UPPER(nom), ' ', prenom) AS Voyageur,
       YEAR(dateNaiss) AS Annee_Naiss
FROM Voyageur
WHERE YEAR(dateNaiss) IN (2008, 2009);

-- 4. Villes comptant au moins 2 voyageurs (1 pt) → Sousse (3), Tunis (2)
SELECT ville, COUNT(*) AS Nb_Voyageurs
FROM Voyageur
GROUP BY ville
HAVING COUNT(*) >= 2
ORDER BY Nb_Voyageurs DESC;

-- 5. Jointure implicite 2 tables : Excursion + Guide (1 pt) → 5 lignes
SELECT E.titre, E.destination, E.prixPers, G.nomGuide, G.langue
FROM Excursion E, Guide G
WHERE E.idGuide = G.idGuide
ORDER BY G.nomGuide ASC;

-- 6. Jointure implicite 3 tables : T1 2026 + montant payé (1 pt) → 6 lignes
SELECT V.nom, V.prenom, E.titre, R.dateRes, R.nbPlaces,
       (E.prixPers * R.nbPlaces) AS Montant_DT
FROM Voyageur V, Reservation R, Excursion E
WHERE V.idVoy = R.idVoy
  AND R.codeExc = E.codeExc
  AND YEAR(R.dateRes) = 2026
  AND MONTH(R.dateRes) IN (1, 2, 3);

-- 7. Jointure + GROUP BY : Recette par excursion (1,5 pt)
-- Résultats : EXC01 (3 res, 1080 DT), EXC04 (2, 960 DT), EXC05 (1, 420 DT), EXC02 (1, 285 DT), EXC03 (1, 140 DT)
SELECT E.codeExc, E.titre,
       COUNT(*) AS Nb_Res,
       SUM(E.prixPers * R.nbPlaces) AS Recette_DT
FROM Excursion E, Reservation R
WHERE E.codeExc = R.codeExc
GROUP BY E.codeExc, E.titre
ORDER BY Recette_DT DESC;

-- 8. Jointure 4 tables + WHERE + GROUP BY + HAVING (1,5 pt)
-- Voyageurs de Sousse : Ben Amor (360+180+285+540 = 1365 DT > 500) ; Mabrouk (320 DT) ; Sassi (140 DT)
SELECT G.nomGuide,
       SUM(E.prixPers * R.nbPlaces) AS CA_Sousse
FROM Guide G, Excursion E, Reservation R, Voyageur V
WHERE G.idGuide = E.idGuide
  AND E.codeExc = R.codeExc
  AND R.idVoy = V.idVoy
  AND V.ville = 'Sousse'
GROUP BY G.idGuide, G.nomGuide
HAVING SUM(E.prixPers * R.nbPlaces) > 500;
