Corrigé — Exercice 1 (4 pts)

1. Vrai / Faux (2 pts) :
• a) Vrai (0,5 pt).
• b) Faux — Une clé primaire est obligatoirement unique et NOT NULL (intégrité d'entité) (0,5 pt).
• c) Faux — AUTO_INCREMENT est réservé à un type numérique entier (INT) (0,5 pt).
• d) Faux — ALTER TABLE modifie la structure tout en conservant les données existantes (sauf si l'on supprime une colonne avec DROP COLUMN) (0,5 pt).

• Erreur 1 (Atomicité — 0,5 pt) : adresseComplete est un attribut composé → à éclater (ex. rue, codePostal, ville).

Exercice 2 : Modélisation — Service « VoltRide » 5 points

Figure DC1B.1 — Schéma Relationnel de la base VoltRide (Trottinette, Location, Abonne).
La start-up de location de trottinettes électriques VoltRide souhaite créer une base de données nommée voltride_db pour gérer son activité :
  • Chaque Trottinette est identifiée par un code (codeTrot, ex. TR01), possède un modèle (modele), une catégorie (categorie : Urbaine ou Tout-terrain) et un tarif horaire en dinars (tarifH).
  • Chaque Abonné possède un numéro auto-incrémenté (idAb), un nom (nomAb), un téléphone (telAb) et sa ville (ville).
  • Chaque Location est identifiée par un numéro auto-incrémenté (numLoc), possède une date (dateLoc), une heure de début entière (heureDeb, ex. 14) et une durée en heures (dureeH). Une trottinette fait l'objet de plusieurs locations, mais chaque location concerne une seule trottinette. Un abonné effectue plusieurs locations, mais chaque location appartient à un seul abonné.
  1. Précisez le type de lien (1-N ou N-N) entre Trottinette et Location, puis entre Abonné et Location. (1 pt)
  2. Écrivez la représentation textuelle complète des 3 tables (Trottinette, Abonne, Location) en soulignant les clés primaires (pk) et en faisant suivre les clés étrangères du symbole # (fk#). (2,5 pts)
  3. Indiquez dans quel ordre il faut insérer les données dans ces 3 tables, puis dans quel ordre il faudrait les supprimer avec DROP TABLE. (1 pt)
  4. Pourquoi ne peut-on pas choisir nomAb comme clé primaire de la table Abonne ? (0,5 pt)
Corrigé — Exercice 2 (5 pts)

1. Types de liens (1 pt) : Trottinette — Location : 1-N (0,5 pt) | Abonne — Location : 1-N (0,5 pt).

2. Modèle relationnel (2,5 pts) :

Trottinette (codeTrot, modele, categorie, tarifH)
Abonne (idAb, nomAb, telAb, ville)
Location (numLoc, dateLoc, heureDeb, dureeH, codeTrot#, idAb#)

3. Ordre (1 pt) : Insertion : Trottinette et Abonne d'abord, puis Location (0,5 pt). Suppression : Location d'abord, puis Trottinette et Abonne (0,5 pt).

4. Choix de clé primaire (0,5 pt) : Deux abonnés peuvent porter le même nom (risque d'homonymes), ce qui violerait la règle d'unicité de la clé primaire.

Exercice 3 : Langage de Définition de Données (LDD) 6 points

On suppose que la base voltride_db et la table Abonne(idAb INT AUTO_INCREMENT PRIMARY KEY, nomAb VARCHAR(40) NOT NULL, telAb VARCHAR(15) NOT NULL, ville VARCHAR(30) NOT NULL) sont déjà créées.

  1. Écrivez la requête SQL de création de la table Trottinette respectant les règles suivantes : (1,5 pt)
    • codeTrot : chaîne de 6 caractères max, clé primaire ;
    • modele : chaîne de 40 caractères max, obligatoire ;
    • categorie : liste fermée parmi 'Urbaine' et 'Tout-terrain', obligatoire ;
    • tarifH : nombre décimal (7 chiffres dont 3 après la virgule), obligatoire et strictement positif.
  2. Écrivez la requête SQL de création de la table Location : (2,5 pts)
    • numLoc : entier auto-incrémenté, clé primaire ;
    • dateLoc : date obligatoire ; heureDeb : entier obligatoire ;
    • dureeH : entier obligatoire, valeur par défaut 1, compris entre 1 et 4 inclus ;
    • codeTrot : clé étrangère vers Trottinette(codeTrot) avec ON DELETE RESTRICT ;
    • idAb : clé étrangère vers Abonne(idAb) avec ON DELETE CASCADE.
  3. Écrivez les 3 requêtes ALTER TABLE permettant d'effectuer les évolutions suivantes : (2 pts)
    • a) Ajouter à la table Abonne une colonne cinAb de type VARCHAR(8), facultative et unique. (1 pt)
    • b) Agrandir la colonne modele de la table Trottinette à VARCHAR(60) (toujours obligatoire). (0,5 pt)
    • c) Renommer la colonne telAb de la table Abonne en numTel (VARCHAR(20) NOT NULL). (0,5 pt)
Corrigé — Exercice 3 : LDD (6 pts) 
-- 1. Création de Trottinette (1,5 pt)
CREATE TABLE Trottinette (
    codeTrot  VARCHAR(6),
    modele    VARCHAR(40) NOT NULL,
    categorie ENUM('Urbaine', 'Tout-terrain') NOT NULL,
    tarifH    DECIMAL(7,3) NOT NULL,
    CONSTRAINT pk_trottinette PRIMARY KEY (codeTrot),
    CONSTRAINT chk_tarif_trot CHECK (tarifH > 0)
);

-- 2. Création de Location (2,5 pts)
CREATE TABLE Location (
    numLoc   INT AUTO_INCREMENT,
    dateLoc  DATE NOT NULL,
    heureDeb INT  NOT NULL,
    dureeH   INT  NOT NULL DEFAULT 1,
    codeTrot VARCHAR(6) NOT NULL,
    idAb     INT        NOT NULL,
    CONSTRAINT pk_location   PRIMARY KEY (numLoc),
    CONSTRAINT chk_duree_loc CHECK (dureeH BETWEEN 1 AND 4),
    CONSTRAINT fk_loc_trot   FOREIGN KEY (codeTrot)
        REFERENCES Trottinette(codeTrot) ON DELETE RESTRICT,
    CONSTRAINT fk_loc_ab     FOREIGN KEY (idAb)
        REFERENCES Abonne(idAb) ON DELETE CASCADE
);

-- 3. Évolutions ALTER TABLE (2 pts)
ALTER TABLE Abonne      ADD cinAb VARCHAR(8) NULL UNIQUE;
ALTER TABLE Trottinette MODIFY modele VARCHAR(60) NOT NULL;
ALTER TABLE Abonne      CHANGE telAb numTel VARCHAR(20) NOT NULL;

Exercice 4 : Manipulation des Données (LMD) et Intégrité 5 points

  1. Insertion multiple : Insérez en une seule requête les deux trottinettes suivantes dans la table Trottinette : (1,5 pt)
    • TR01, Xiaomi Pro 2, Urbaine, 12.000 DT
    • TR02, Dualtron Mini, Tout-terrain, 18.500 DT
  2. Insertion simple : Insérez dans la table Abonne l'abonné 'Sami Khelil', téléphone '55443322', ville 'Sousse', sans numéro de CIN (cinAb non renseigné). (1 pt)
  3. Mise à jour : Réduisez de 2.000 DT le tarif horaire (tarifH) de toutes les trottinettes de catégorie 'Tout-terrain'. (1 pt)
  4. Suppression ciblée : Supprimez de la table Location la location portant le numéro 24. (0,5 pt)
  5. Analyse d'intégrité : Expliquez précisément la réaction du SGBDR pour chacune des deux commandes ci-dessous : (1 pt — 0,5 pt × 2)
    • a) DELETE FROM Trottinette WHERE codeTrot = 'TR01'; (sachant que la trottinette 'TR01' possède 4 locations enregistrées).
    • b) INSERT INTO Location (dateLoc, heureDeb, dureeH, codeTrot, idAb) VALUES ('2026-12-05', 14, 6, 'TR01', 1);
Corrigé — Exercice 4 : LMD et Intégrité (5 pts) 
-- 1. Insertion multiple dans Trottinette (1,5 pt)
INSERT INTO Trottinette (codeTrot, modele, categorie, tarifH) VALUES
('TR01', 'Xiaomi Pro 2',  'Urbaine',      12.000),
('TR02', 'Dualtron Mini', 'Tout-terrain', 18.500);

-- 2. Insertion simple dans Abonne (1 pt)
INSERT INTO Abonne (nomAb, numTel, ville, cinAb)
VALUES ('Sami Khelil', '55443322', 'Sousse', NULL);

-- 3. Mise à jour conditionnelle (1 pt)
UPDATE Trottinette
SET tarifH = tarifH - 2
WHERE categorie = 'Tout-terrain';

-- 4. Suppression ciblée (0,5 pt)
DELETE FROM Location
WHERE numLoc = 24;

5. Analyse d'intégrité (1 pt) :
• a) La suppression est bloquée (refusée) grâce à la clause ON DELETE RESTRICT définie sur fk_loc_trot, car la trottinette 'TR01' est encore référencée par 4 lignes dans la table fille Location (0,5 pt).
• b) L'insertion est refusée pour violation de la contrainte de domaine CHECK (dureeH BETWEEN 1 AND 4) : la durée saisie (6 heures) dépasse la borne maximale autorisée (0,5 pt).
