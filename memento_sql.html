MÉMENTO SQL — Modélisation, LDD & LMD

Recto — 1 / 2

1. Modèle Relationnel & Intégrité

  • Entité → Table | Attribut → Champ | Occurrence → Ligne.
  • Clé primaire (PK) #champ : unique et non nulle.
  • Clé étrangère (FK) champ# : référence la PK d'une table mère (même type obligatoire).
  • Lien 1-N : la PK côté 1 migre comme FK dans la table côté N.
  • Lien N-N : création d'une table d'association ayant une PK composée des deux FK + attributs propres.
  • Règles d'or : attributs atomiques (pas de nomComplet) et non calculés (stocker dateNaiss, pas age).
  • 3 Intégrités : Domaine (type/bornes), Entité (PK unique/non nulle), Référentielle (toute FK existe dans la table mère).

3. LDD — Création de la Base et des Tables (CREATE)

DROP DATABASE IF EXISTS boutique_info;
CREATE DATABASE boutique_info;
USE boutique_info;

CREATE TABLE Produit (
  refProd     VARCHAR(10),
  designation VARCHAR(80)   NOT NULL,
  prixUnit    DECIMAL(10,3) NOT NULL,
  qteStock    INT           NOT NULL DEFAULT 0,
  CONSTRAINT pk_prod  PRIMARY KEY (refProd),
  CONSTRAINT chk_prix CHECK (prixUnit > 0)
);

CREATE TABLE LigneCommande (
  numCmd  INT,
  refProd VARCHAR(10),
  qteCmd  INT NOT NULL,
  CONSTRAINT pk_lig   PRIMARY KEY (numCmd, refProd),
  CONSTRAINT fk_l_cmd FOREIGN KEY (numCmd)
    REFERENCES Commande(numCmd) ON DELETE CASCADE,
  CONSTRAINT fk_l_prd FOREIGN KEY (refProd)
    REFERENCES Produit(refProd) ON DELETE RESTRICT
);
Contraintes essentielles :
  • NOT NULL : champ obligatoire.
  • AUTO_INCREMENT : numérotation auto (colonne INT PK uniquement).
  • DEFAULT val : valeur par défaut.
  • UNIQUE : pas de doublon (autorise NULL, plusieurs possibles/table).
  • CHECK (cond) : règle métier.
Options de clé étrangère :
  • ON DELETE RESTRICT (défaut) : bloque la suppression mère si des lignes filles existent.
  • ON DELETE CASCADE : supprime automatiquement les lignes filles liées.
  • ON UPDATE CASCADE : répercute la modif. de la PK mère sur la FK fille.
Utilitaires : SHOW TABLES; | DESCRIBE Table;

4. LDD — Modification (ALTER TABLE) & Suppression (DROP TABLE)

ActionSyntaxe MariaDB / MySQL
Ajouter colonneALTER TABLE T ADD col TYPE [cstr];
Modifier type/cstrALTER TABLE T MODIFY col TYPE [cstr];
Renommer colonneALTER TABLE T CHANGE anc nouv TYPE;
Supprimer colonneALTER TABLE T DROP COLUMN col;
Ajouter contrainteALTER TABLE T ADD CONSTRAINT nom ...;
Supprimer une FKALTER TABLE T DROP FOREIGN KEY nom;
 
-- Exemples d'évolution
ALTER TABLE Client ADD email VARCHAR(80) UNIQUE;
ALTER TABLE Client MODIFY tel VARCHAR(20);
ALTER TABLE Produit ADD CONSTRAINT chk_st CHECK (qteStock >= 0);

-- Suppression de table (filles AVANT mères !)
DROP TABLE IF EXISTS LigneCommande;
DROP TABLE IF EXISTS Commande;
Ordre strict : CREATE / INSERT → Mères puis Filles | DROP / DELETE → Filles puis Mères.

5. LMD — Manipulation des Données (INSERT, UPDATE, DELETE)

-- Insertion simple
INSERT INTO Client (nom, prenom, ville, tel, dateInscr)
VALUES ('Ben Salem', 'Sami', 'Sousse', '22451200', '2025-09-12');

-- Insertion multiple (NULL sans apostrophes)
INSERT INTO Client (nom, prenom, ville, tel, dateInscr) VALUES
('Trabelsi', 'Ines', 'Tunis',  '55890123', '2025-10-03'),
('Mansouri', 'Aya',  'Sousse', NULL,       '2026-01-15');
-- Mise à jour (virgules dans SET, JAMAIS AND)
UPDATE Produit
SET prixUnit = prixUnit * 1.10, qteStock = qteStock + 5
WHERE categorie = 'Accessoire';

-- Suppression ciblée
DELETE FROM Produit WHERE refProd = 'P06';
DANGER : Sans WHERE, UPDATE modifie toute la table et DELETE la vide totalement !

6. Structure SELECT & Ordre des Clauses

SELECT [DISTINCT] col1 [AS alias1], expr ...
FROM Table1 [T1], Table2 [T2]
[WHERE condition_lignes_et_jointures]
[GROUP BY col_groupe1, ...]
[HAVING condition_sur_les_groupes]
[ORDER BY col1 [ASC|DESC], col2 [ASC|DESC]]
[LIMIT n];
Exécution : 1.FROM→ 2.WHERE→ 3.GROUP BY→ 4.HAVING→ 5.SELECT→ 6.ORDER BY

9. Agrégation, Regroupements (GROUP BY) & WHERE vs HAVING

Fonction d'agrégationRôle (face à NULL)
COUNT(*)Nb total de lignes (inclut NULL)
COUNT(col)Nb de valeurs non nulles (ignore NULL)
COUNT(DISTINCT col)Nb de valeurs distinctes non nulles
SUM(col) / AVG(col)Somme / Moyenne (ignorent NULL)
MIN(col) / MAX(col)Minimum / Maximum (nombres, dates, textes)
Règle d'or GROUP BY : toute colonne de SELECT hors agrégation doit figurer dans GROUP BY.
CritèreWHEREHAVING
MomentAvant GROUP BYAprès GROUP BY
CibleFiltre les lignesFiltre les groupes
AgrégationInterditeAutorisée
ExempleWHERE qteStock > 0HAVING AVG(prix) > 200
 
-- Catégories ayant >= 2 produits en stock
SELECT categorie, COUNT(*) AS Nb FROM Produit
WHERE qteStock > 0 GROUP BY categorie HAVING COUNT(*) >= 2;

10. Jointures Implicites via WHERE (2, 3 et 4 tables)

-- Exemple complet : 4 tables → 3 conditions de jointure + WHERE + GROUP BY + HAVING
-- Clients de Sousse ayant dépensé >= 2500 DT au total
SELECT C.nom, C.prenom,
       COUNT(DISTINCT Cmd.numCmd) AS Nb_Cmd,
       SUM(P.prixUnit * L.qteCmd) AS CA_Client
FROM Client C, Commande Cmd, LigneCommande L, Produit P
WHERE C.idClt = Cmd.idClt          -- Jointure 1 (Client ↔ Commande)
  AND Cmd.numCmd = L.numCmd        -- Jointure 2 (Commande ↔ LigneCommande)
  AND L.refProd = P.refProd        -- Jointure 3 (LigneCommande ↔ Produit)
  AND C.ville = 'Sousse'           -- Filtre métier
GROUP BY C.idClt, C.nom, C.prenom
HAVING SUM(P.prixUnit * L.qteCmd) >= 2500
ORDER BY CA_Client DESC;
Méthode infaillible en 4 étapes :
  • 1. Lister les tables nécessaires dans FROM avec des alias courts (Client C, Commande Cmd).
  • 2. Règle des N − 1 jointures : pour N tables, écrire exactement N − 1 égalités PK = FK dans WHERE pour éviter le produit cartésien.
  • 3. Préfixer toute colonne présente dans plusieurs tables (C.idClt, Cmd.numCmd).
  • 4. Compter sans doublon : utiliser COUNT(DISTINCT Cmd.numCmd) si une jointure multiplie les lignes.

11. Top 6 des Pièges à Éviter en Devoir

  • = NULL interdit : toujours écrire IS NULL ou IS NOT NULL.
  • AND prioritaire sur OR : encadrer les OR par des (...).
  • Agrégation dans WHERE : interdite → utiliser HAVING après GROUP BY.
  • Oubli d'une jointure : provoque un produit cartésien (vérifier N − 1 liens).
  • UPDATE avec AND : dans SET, séparer les colonnes par une virgule ,.
  • Alias dans WHERE : interdit (exécuté avant SELECT) ; autorisé dans ORDER BY.
