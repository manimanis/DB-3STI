1. Situation problème : Le cahier des charges évolue ! 15 min — Oral

La base boutique_info de TechStore a été mise en service la semaine dernière. Dès les premiers jours d'utilisation, le gérant vous envoie 4 demandes urgentes :

  1. « Je veux enregistrer l'adresse e-mail de chaque client, et deux clients ne doivent jamais pouvoir utiliser le même e-mail. »
  2. « Un vendeur a saisi par erreur un produit avec un prix négatif (-45.000 DT) et un stock à -3. La base doit bloquer automatiquement ces erreurs ! »
  3. « Si j'annule et supprime une Commande, je veux que ses lignes dans LigneCommande disparaissent automatiquement. En revanche, on doit m'interdire de supprimer un Client qui a déjà passé des commandes. »
  4. « Attention : la base contient déjà des clients. Hors de question de tout effacer et recommencer de zéro ! »

Question d'ouverture : Comment modifier la structure de tables existantes et ajouter ces garde-fous directement au niveau du SGBDR ?

Guide Enseignant — Solutions techniques attendues
  • Demande 1 (Email unique) : Ajouter la colonne puis lui associer une contrainte UNIQUE (ex. : uq_client_email) pour rejeter les doublons à l'insertion.
  • Demande 2 (Prix et stock positifs) : Définir des contraintes CHECK (prixUnit > 0) et CHECK (qteStock >= 0) afin que le SGBD bloque matériellement toute saisie invalide.
  • Demande 3 (Gestion des suppressions) :
    • Sur la clé étrangère numCmd de LigneCommande : appliquer ON DELETE CASCADE (supprimer la commande entraîne ses lignes).
    • Sur la clé étrangère idClt de Commande : appliquer ON DELETE RESTRICT (bloque la suppression d'un client s'il possède des commandes actives).
  • Demande 4 (Ne rien perdre) : Utiliser l'instruction ALTER TABLE (et non pas DROP TABLE + recréation) pour faire évoluer le schéma en place sans toucher aux données déjà saisies.

2. Synthèse : Contraintes avancées, ALTER TABLE, DROP TABLE et CASCADE 25 min — Trace écrite

A. Contraintes avancées (UNIQUE et CHECK)

  • UNIQUE : Garantit que toutes les valeurs d'une colonne sont distinctes (pas de doublon), mais contrairement à PRIMARY KEY, une colonne UNIQUE peut accepter des valeurs NULL et une table peut en posséder plusieurs.
  • CHECK (condition) : Vérifie qu'une valeur respecte une règle métier avant d'accepter l'insertion ou la modification (ex. : CHECK (prixUnit > 0), CHECK (qteStock >= 0)).

B. Modifier la structure d'une table : ALTER TABLE

Action souhaitée Syntaxe MariaDB / MySQL
Ajouter une colonne ALTER TABLE Table ADD nomCol TYPE [contraintes];
Modifier le type ou les contraintes d'une colonne (même nom) ALTER TABLE Table MODIFY nomCol NOUVEAU_TYPE [contraintes];
Renommer une colonne (et préciser son type) ALTER TABLE Table CHANGE ancienNom nouveauNom TYPE [contraintes];
Supprimer une colonne ALTER TABLE Table DROP COLUMN nomCol;
Ajouter une contrainte nommée (UNIQUE, CHECK, FK) ALTER TABLE Table ADD CONSTRAINT nom_cstr ... ;
Supprimer une clé étrangère ALTER TABLE Table DROP FOREIGN KEY nom_fk;

C. Supprimer une table : DROP TABLE

DROP TABLE NomTable;
DROP TABLE IF EXISTS NomTable; -- Évite une erreur si la table n'existe pas

Règle d'ordre : À cause de l'intégrité référentielle, on supprime toujours les tables filles avant les tables mères (ex. : LigneCommande → Commande → Client et Produit).

D. Gestion des suppressions et modifications liées (Clé étrangère)

Figure 4.1 — Actions référentielles : sécurité RESTRICT (bouclier anti-suppression) vs propagation CASCADE (suppression liée).

Lorsqu'on supprime (ON DELETE) ou modifie (ON UPDATE) une ligne de la table mère, le SGBDR applique la règle définie sur la clé étrangère de la table fille :

Option Comportement sur la table fille Cas d'usage dans TechStore
ON DELETE RESTRICT (défaut) Bloque la suppression dans la table mère tant qu'il existe au moins une ligne liée dans la table fille. Empêcher de supprimer un Client qui a des Commandes, ou un Produit déjà commandé.
ON DELETE CASCADE Supprime automatiquement toutes les lignes liées dans la table fille. Supprimer une Commande efface automatiquement ses lignes dans LigneCommande.
ON UPDATE CASCADE Si la clé primaire mère est modifiée, la clé étrangère fille est mise à jour automatiquement. Si refProd passe de P01 à PC01, LigneCommande suit automatiquement.

3. TP guidé : Scénario d'évolution sur « boutique_info » 40 min — Sur machine

Ouvrez phpMyAdmin, sélectionnez votre base boutique_info (créée en séance 3), puis réalisez chaque étape dans l'onglet SQL en vérifiant le résultat avec DESCRIBE ou SHOW CREATE TABLE.

  1. Ajouter une colonne et une contrainte UNIQUE :
    • Ajoutez à la table Client une colonne email de type VARCHAR(80) (facultative).
    • Ajoutez ensuite une contrainte nommée uq_client_email imposant l'unicité de email.
  2. Modifier et renommer des colonnes :
    • Agrandissez la colonne tel de Client pour passer de VARCHAR(15) à VARCHAR(20) (toujours facultative).
    • Ajoutez une colonne temporaire remarque VARCHAR(100) dans Client, renommez-la en notes (VARCHAR(150)) avec CHANGE, puis supprimez-la avec DROP COLUMN.
  3. Ajouter des contraintes CHECK :
    • Sur Produit : ajoutez chk_prix (prixUnit > 0) et chk_stock (qteStock >= 0).
    • Sur LigneCommande : ajoutez chk_qte_cmd (qteCmd > 0).
  4. Activer ON DELETE CASCADE sur LigneCommande :
    • Supprimez la clé étrangère existante fk_lig_cmd de LigneCommande.
    • Recréez-la avec ON DELETE CASCADE et ON UPDATE CASCADE.
    • Faites de même sur fk_cmd_client (table Commande) et fk_lig_prod (table LigneCommande) avec ON DELETE RESTRICT et ON UPDATE CASCADE.
  5. Tester DROP TABLE et l'ordre de suppression :
    • Créez une petite table brouillon Promotion(idPromo INT PRIMARY KEY, refProd VARCHAR(10), taux INT, FOREIGN KEY (refProd) REFERENCES Produit(refProd)).
    • Essayez d'exécuter DROP TABLE Produit; — observez le message d'erreur du SGBDR.
    • Supprimez proprement la table brouillon Promotion avec DROP TABLE IF EXISTS Promotion;.
Corrigé — Script complet d'évolution LDD (boutique_info) 
USE boutique_info;

-- 1. Ajout de email + contrainte UNIQUE
ALTER TABLE Client ADD email VARCHAR(80) NULL;
ALTER TABLE Client ADD CONSTRAINT uq_client_email UNIQUE (email);

-- 2. MODIFY, CHANGE et DROP COLUMN
ALTER TABLE Client MODIFY tel VARCHAR(20) NULL;
ALTER TABLE Client ADD remarque VARCHAR(100);
ALTER TABLE Client CHANGE remarque notes VARCHAR(150);
ALTER TABLE Client DROP COLUMN notes;

-- 3. Ajout des contraintes CHECK
ALTER TABLE Produit       ADD CONSTRAINT chk_prix    CHECK (prixUnit > 0);
ALTER TABLE Produit       ADD CONSTRAINT chk_stock   CHECK (qteStock >= 0);
ALTER TABLE LigneCommande ADD CONSTRAINT chk_qte_cmd CHECK (qteCmd > 0);

-- 4. Mise à jour des clés étrangères (CASCADE / RESTRICT)
ALTER TABLE LigneCommande DROP FOREIGN KEY fk_lig_cmd;
ALTER TABLE LigneCommande
  ADD CONSTRAINT fk_lig_cmd FOREIGN KEY (numCmd)
  REFERENCES Commande(numCmd)
  ON DELETE CASCADE ON UPDATE CASCADE;

ALTER TABLE Commande DROP FOREIGN KEY fk_cmd_client;
ALTER TABLE Commande
  ADD CONSTRAINT fk_cmd_client FOREIGN KEY (idClt)
  REFERENCES Client(idClt)
  ON DELETE RESTRICT ON UPDATE CASCADE;

ALTER TABLE LigneCommande DROP FOREIGN KEY fk_lig_prod;
ALTER TABLE LigneCommande
  ADD CONSTRAINT fk_lig_prod FOREIGN KEY (refProd)
  REFERENCES Produit(refProd)
  ON DELETE RESTRICT ON UPDATE CASCADE;

-- 5. Test DROP TABLE (table brouillon)
CREATE TABLE Promotion (
    idPromo INT PRIMARY KEY,
    refProd VARCHAR(10),
    taux    INT,
    CONSTRAINT fk_promo_prod FOREIGN KEY (refProd) REFERENCES Produit(refProd)
);

-- DROP TABLE Produit;  -- Échoue : référencée par Promotion et LigneCommande !
DROP TABLE IF EXISTS Promotion; -- Réussit : table fille supprimée proprement

4. Atelier « Chasse aux bugs LDD » 15 min

Bug 1 — Suppression impossible d'une table

DROP TABLE Client;
DROP TABLE Commande;
DROP TABLE LigneCommande;

Question : Pourquoi la première ligne renvoie-t-elle une erreur Cannot delete or update a parent row ? Dans quel ordre faut-il exécuter ces 3 commandes ?

Corrigé — Bug 1 Client est référencée par Commande, qui est elle-même référencée par LigneCommande. Il faut supprimer de la fille vers la mère :
DROP TABLE LigneCommande; → DROP TABLE Commande; → DROP TABLE Client;

Bug 2 — Confusion entre MODIFY et CHANGE

-- L'élève veut renommer la colonne "ville" en "gouvernorat"
ALTER TABLE Client MODIFY ville gouvernorat VARCHAR(30);
Corrigé — Bug 2 MODIFY ne sert qu'à changer le type ou les contraintes en gardant le même nom. Pour renommer une colonne, il faut utiliser CHANGE :
ALTER TABLE Client CHANGE ville gouvernorat VARCHAR(30) NOT NULL;

Bug 3 — Risque caché de ON DELETE CASCADE

Un développeur débutant met ON DELETE CASCADE sur la clé étrangère Commande(idClt) → Client(idClt). Que se passe-t-il si un employé supprime par erreur un client qui a passé 25 commandes sur l'année ?

Corrigé — Bug 3 Les 25 commandes (et toutes leurs lignes dans LigneCommande !) seraient détruites automatiquement, faussant toute la comptabilité de la boutique. C'est pourquoi on privilégie ON DELETE RESTRICT sur les entités métier critiques.

5. Application en autonomie : Évolution de la table « Fournisseur » 15 min

On suppose que TechStore ajoute la table suivante à sa base :

CREATE TABLE Fournisseur (
    idFourn INT PRIMARY KEY,
    nom     VARCHAR(30) NOT NULL,
    tel     VARCHAR(15)
);

Écrivez les 4 requêtes SQL permettant d'effectuer les modifications suivantes :

  1. Ajouter une colonne matriculeFisc de type VARCHAR(20) obligatoire et unique.
  2. Agrandir la taille de la colonne nom à 60 caractères (en gardant NOT NULL).
  3. Ajouter une colonne delaiLivraison (entier, valeur par défaut 3) avec une contrainte vérifiant qu'il est compris entre 1 et 30 jours.
  4. Renommer la colonne tel en telephone (VARCHAR(20)).
Corrigé — Requêtes ALTER TABLE sur Fournisseur 
-- 1. Ajouter matriculeFisc obligatoire et unique
ALTER TABLE Fournisseur ADD matriculeFisc VARCHAR(20) NOT NULL UNIQUE;

-- 2. Agrandir nom à 60 caractères
ALTER TABLE Fournisseur MODIFY nom VARCHAR(60) NOT NULL;

-- 3. Ajouter delaiLivraison avec DEFAULT et CHECK
ALTER TABLE Fournisseur ADD delaiLivraison INT DEFAULT 3;
ALTER TABLE Fournisseur ADD CONSTRAINT chk_delai CHECK (delaiLivraison >= 1 AND delaiLivraison <= 30);

-- 4. Renommer tel en telephone
ALTER TABLE Fournisseur CHANGE tel telephone VARCHAR(20);

6. Quiz éclair de clôture 10 min

1. Différence clé : Citez deux différences entre une contrainte PRIMARY KEY et une contrainte UNIQUE.
Réponse : 1) Une table ne peut avoir qu'une seule PRIMARY KEY, mais plusieurs colonnes UNIQUE. 2) PRIMARY KEY interdit NULL, alors que UNIQUE autorise NULL (sauf si on ajoute NOT NULL).
2. Vrai ou Faux : « L'instruction ALTER TABLE efface les données déjà enregistrées dans la table. »
Réponse : Faux — ALTER TABLE modifie uniquement la structure tout en conservant les données existantes (sauf si on utilise DROP COLUMN sur une colonne remplie).
3. Syntaxe : Quelle clause de ALTER TABLE utilise-t-on pour renommer une colonne : MODIFY ou CHANGE ?
Réponse : CHANGE (en précisant l'ancien nom, le nouveau nom et le type).
4. Cascade : Que fait ON DELETE CASCADE sur la table LigneCommande lorsqu'on supprime la commande n°5 dans Commande ?
Réponse : Le SGBDR supprime automatiquement toutes les lignes de LigneCommande dont numCmd vaut 5.
5. Sécurité : Quelle précaution simple évite qu'un script contenant DROP TABLE Promotion; ne plante si la table a déjà été supprimée ?
Réponse : Écrire DROP TABLE IF EXISTS Promotion;.
